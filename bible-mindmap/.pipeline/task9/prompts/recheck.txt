작업 폴더는 현재 폴더(bible-mindmap)다. 이 실행에서 너는 batch 05 의 '교정 후 재감사자'다. 파일을 고치지 마라. 찾아서 보고만 하라.

배경: 감사 지적을 받아 `.pipeline/task9/final.json` 에 기계 교정을 적용했다. 헬라어 ευ → 유 계열, 어말 카마츠+헤 → -â, 어두 ῥ → ㄹ, 유성 쉐바 → ĕ, 그리고 개별 손질 몇 건이다. 교정 기록은 같은 파일의 `changes` 배열에 있다.

batch 02 에서 같은 종류의 정리가 **회귀 13건**을 만든 적이 있다. note 를 통째로 지워 멀쩡한 설명까지 날린 것이다. 그런 일이 이번에도 있는지 보는 것이 네 일이다.

1. `.pipeline/task9/final.json` 의 `changes` 를 하나씩 보고, 교정 **후** 값이 배포 데이터 선례와 맞는지 확인하라.
2. 교정 때문에 note 가 실제 값과 어긋나게 된 항목이 있는가. 300개 전수로 검사하라.
3. 교정 과정에서 사라지면 안 되는 설명이 사라진 항목이 있는가.
4. 규칙이 **잘못 적용된** 자리가 있는가. 특히 이런 곳을 의심하라.
   - 어말 -āh 를 -â 로 바꿨는데 사실 마피크가 붙은 자음 헤였던 낱말
   - ευ 를 유로 합쳤는데 사실 ε 와 υ 가 다른 음절에 속하던 낱말
   - 어두 ῥ 에서 흐를 뗐는데 그러면 다른 낱말과 한글 표기가 겹치는 자리
5. 검사는 눈으로 훑지 말고 node 스크립트로 전수로 하라.

출력은 `.pipeline/task9/audits/recheck.json` 하나뿐이다. 다른 파일은 만들지도 고치지도 마라.

형식(마크다운 코드펜스 없이 JSON만):
{"scope":"batch-05-recheck","checked":<개수>,"regressions":[{"strong":"…","issue":"…","evidence":"…","severity":"high|medium|low"}],"remaining":[{"strong":"…","issue":"…","severity":"…"}],"summary":"한국어 두세 문장"}

근거 없는 지적은 하지 마라. 문제가 없으면 빈 배열로 둬라.
다 쓴 뒤 node -e 로 JSON.parse 하고 "recheck OK regressions=<개수> remaining=<개수>" 한 줄만 보고하라.
