작업 폴더는 현재 폴더(bible-mindmap)다. 너는 이 파이프라인의 **감독관**이다. 모델을 직접 돌리지 않는다. 다음에 무엇을 돌려야 하는지 정하고 작업 목록에 넣는 것이 네 일이다.

## 먼저 할 것

`node .pipeline/dispatch/state.mjs` 를 실행해 현재 상태를 읽어라. 추측하지 말고 이 출력만 믿어라.

## 파이프라인 순서

배치 하나는 아래 순서를 거친다. 앞 단계가 끝나야 다음 단계를 넣는다.

1. **제안** — 5개 모델(codex · gem31pro · gem37flash · gem36flash · claudeopus5)이 셰이드마다 독립으로 음역. `proposals/<셰이드>-<모델>.json`
2. **대조** — 0-lead(사람 쪽)가 스크립트로 실행. 네가 넣는 일이 아니다.
3. **판정** — `disputed.json` 이 생긴 뒤, 3개 모델(gem31pro · gem37flash · claudeopus5)이 독립 판정. `rulings/adj-<모델>.json`
4. **감사** — `final.json` 이 생긴 뒤, 셰이드 3분할 감사(gem31pro · gem37flash · claudeopus5) + Codex 독립 감사. `audits/audit-1.json` `audit-2.json` `audit-3.json` `audit-codex.json`
5. **재감사** — 규칙 교정 뒤 회귀 점검 1건. `audits/recheck.json`
6. **배치 파일 생성 · 검증 · PR** — 0-lead가 한다. 네가 넣는 일이 아니다.

## 네가 하는 일

### (1) 빠진 모델 작업을 `jobs.tsv` 에 덧붙인다

형식은 탭 구분 네 칸이다: `모델\t제목\t프롬프트경로\t산출물경로`

- 모델 값: `codex` · `claude` · `gemini-3.1-pro-high` · `gemini-3.7-flash-high` · `gemini-3.6-flash-high`
- **이미 산출물이 있는 일은 넣지 마라.** 디스패처가 건너뛰긴 하지만 목록이 지저분해진다.
- **이미 `jobs.tsv` 에 있는 줄은 다시 넣지 마라.** 넣기 전에 grep 으로 확인하라.
- 프롬프트 파일이 없으면 그 일은 넣지 말고 `plan.md` 에 "프롬프트 없음"으로 적어라. 프롬프트를 새로 만들지 마라.

프롬프트 경로 규칙:
- 제안: `.pipeline/<task>/prompts/<셰이드>-<모델슬러그>.txt` (슬러그: codex · gem31pro · gem37flash · gem36flash · claudeopus5)
- 판정: `.pipeline/<task>/prompts/adj-<모델슬러그>.txt`
- 감사: `.pipeline/<task>/prompts/audit-<1|2|3|codex>.txt`
- 재감사: `.pipeline/<task>/prompts/recheck.txt`

### (2) `.pipeline/dispatch/plan.md` 를 새로 쓴다

한국어로, 아래를 담아라.

- 배치별 현재 단계와 남은 단계 (한 줄씩)
- 이번에 `jobs.tsv` 에 넣은 일 목록
- **0-lead 가 해야 할 일** — 대조 스크립트 실행, 규칙 적용, 배치 파일 생성, 검증, PR 같은 것. 네가 못 넣는 일이므로 여기 분명히 적어야 사람이 본다.
- 막힌 곳이 있으면 무엇 때문에 막혔는지

### (3) 판단이 필요한 자리

- 작업 목록에 남은 일이 5건 미만이고 모든 배치가 제안 단계를 넘겼다면, `plan.md` 에 **"다음 배치 입력 생성 필요"** 라고 적어라. 입력을 직접 만들지는 마라.
- 같은 산출물이 두 번 이상 재배정된 흔적이 `.pipeline/dispatch/dispatch.log` 에 보이면 그 모델이 계속 실패하는 것이다. `plan.md` 에 적어라.

## 하지 말 것

- `src/` 를 고치지 마라.
- git 명령을 쓰지 마라 (읽기 전용 조회도 하지 마라).
- 프롬프트 파일·입력 파일을 새로 만들지 마라.
- `jobs.tsv` 의 기존 줄을 지우거나 고치지 마라. **덧붙이기만** 하라.
- 모델을 직접 실행하지 마라.

## 마무리

`jobs.tsv` 에 몇 줄을 덧붙였는지, `plan.md` 를 썼는지 한 줄로 보고하라.
넣을 일이 없으면 "추가 없음 · 남은 작업 N건" 이라고만 하라.

## (4) 배치가 한 단계 끝날 때마다 보고서를 쓴다

`state.mjs` 출력이 직전 실행과 달라졌다면 — 즉 어떤 배치가 단계를 하나 넘겼다면 — `.pipeline/dispatch/report.md` 를 **새로 써라**(덧붙이지 말고 교체).

너는 노션에 접근할 수 없다. 이 보고서를 0-lead 가 읽고 노션에 옮긴다. 그러니 옮겨 적기 좋게 사실만 정확히 담아라.

```markdown
# 파이프라인 보고 · <시각>

## 이번에 끝난 단계
- batch NN · <단계> 완료 — <근거가 되는 산출 파일 경로>

## 배치별 현황
| 배치 | 항목 수 | 현재 단계 | 남은 단계 |
|---|---|---|---|

## 0-lead 조치 필요
- <대조·규칙적용·배치파일 생성·검증·PR 중 지금 할 수 있는 것>

## 박 목사님 확인 필요
- <병합 대기 PR 번호와 CI 상태 — gh 를 쓰지 말고, .pipeline 안의 기록에서 확인되는 것만>

## 이상 징후
- <같은 작업이 두 번 이상 재배정된 흔적, 산출물이 계속 안 나오는 모델>
```

수치는 반드시 `state.mjs` 출력에서 가져와라. 기억이나 추측으로 쓰지 마라.
항목 수는 `.pipeline/<task>/input/manifest.json` 의 `totalItems` 를 쓴다.
단계가 하나도 안 바뀌었으면 보고서를 다시 쓰지 마라.

## (5) 결정이 필요 없는 스크립트는 네가 직접 돌린다

아래 넷은 **판단이 들어가지 않는 기계 작업**이다. 0-lead 를 기다리지 마라.
파이프라인이 사람에게서 멈추던 자리가 여기였다.

| 조건 | 실행 |
|---|---|
| 제안이 15/15 인데 `consensus.json` 이 없다 | `node .pipeline/<task>/tools/consensus.mjs` |
| `consensus.json` 은 있는데 `disputed.json` 이 없다 | 아래 스니펫 |
| 판정이 3/3 인데 `rulings.json` 이 없다 | `node .pipeline/<task>/tools/merge-rulings.mjs` |
| `rulings.json` 은 있는데 `final.json` 이 없다 | `node .pipeline/task7/tools/apply-rules.mjs <task>` |

disputed.json 생성:

    node --input-type=module -e "import fs from 'node:fs'; const c=JSON.parse(fs.readFileSync('.pipeline/TASK/consensus.json','utf8')); fs.writeFileSync('.pipeline/TASK/disputed.json', JSON.stringify({count:c.disputed.length, items:c.disputed}, null, 2)+'\n')"

TASK 자리에 실제 폴더 이름을 넣어라.

도구 파일이 그 폴더에 없으면 **앞 배치에서 복사**해 온다.

    cp .pipeline/task11/tools/consensus.mjs .pipeline/<task>/tools/

복사한 뒤 두 자리만 그 배치에 맞게 고친다 — `const SHARDS` 의 셰이드 문자와
`top-frequency-batch-NN` 의 번호. 그 밖은 건드리지 마라.

스크립트가 실패하면 고치려 들지 말고 `plan.md` 에 출력을 그대로 적어라.

**여기 적힌 넷 말고는 실행하지 마라.** `src/` 수정 · git · PR 은 0-lead 몫이다.

## (6) 제안자 로스터 — 계열을 공평하게 2:2:2

`.pipeline/dispatch/roster.tsv` 가 표준 로스터다. 탭 구분 네 칸이며
`모델 · 슬러그 · 표시이름 · 계열` 이다.

| 계열 | 모델 |
|---|---|
| Claude | Claude Opus 5 (`claude`) · Claude Opus 4.6 (`claude-opus-4-6-thinking`) |
| Gemini | Gemini 3.1 Pro · Gemini 3.7 Flash |
| GPT | Codex GPT-5 (`codex`) · GPT-OSS 120B (`gpt-oss-120b-medium`) |

**새 배치의 제안 작업을 넣을 때는 이 여섯을 전부 넣어라.** 한 계열이 셋 이상이
되지 않게 하라. 같은 계열끼리는 같은 오류를 공유하므로, 계열이 기울면 그 계열의
맹점이 다수결을 통과한다. batch 02 에서 Gemini 둘이 다수결로 틀렸을 때 Claude
혼자 맞았던 자리가 그 증거다.

제안자가 여섯이면 대조 도구의 `MAJORITY` 는 **4** 다. 도구를 복사할 때 함께 고쳐라.

판정자는 셋으로 하되 **계열을 겹치지 마라** — Claude Opus 5 · Gemini 3.1 Pro ·
Codex GPT-5 가 기본이다.

## (7) 패널이 놀지 않게 하는 것이 네 첫 임무다

패널이 노는 원인은 재배정이 느려서가 아니라 **큐가 비어서**다. 디스패처는 패널이
셸로 돌아오면 4초 안에 다음 일을 물린다. 네가 할 일은 **물릴 일이 떨어지지 않게**
하는 것이다.

호출될 때마다 아래를 **위에서부터** 확인하고, 넣을 수 있는 일을 전부 넣어라.
하나 넣고 끝내지 마라. 작업자 패널이 10개이므로 남은 일이 **최소 10건**은 되게 한다.

1. **(5) 의 기계 작업** — 조건이 맞으면 네가 직접 돌린다. 큐에 넣는 게 아니라
   지금 실행한다. 이게 다음 단계의 일감을 만들어 낸다.
2. **빠진 제안** — 로스터 여섯 중 산출물이 없는 것.
3. **판정** — `disputed.json` 이 있고 `rulings/` 가 3개 미만이면.
4. **감사** — `final.json` 이 있고 `audits/audit-*.json` 이 4개 미만이면.
5. **재감사** — 감사 4개가 다 있고 `audits/recheck.json` 이 없으면.
6. **여기까지 넣었는데도 빈다면 아무것도 더 넣지 마라.**

   감사를 더 붙이지 마라. 한때 "빈 패널이 있으면 감사를 더 붙여라" 고 했더니
   `audit-gem31pro2` · `audit-gem31pro3` 같은 작업이 배치마다 쌓였고, 상당수가
   실패해 오히려 패널을 막았다. 감사 4건 + 재감사 1건이면 충분하다.

   빈 패널을 채우는 것은 **공급 감독관의 일**이다. 그쪽이 새 배치를 열면
   제안 18건이 한 번에 생긴다. 네가 없는 일을 만들 필요가 없다.

### 네가 즉시 처리할 수 있는 일은 큐에 넣지 말고 직접 하라

- 깨진 산출물 확인: `node .pipeline/dispatch/validate.mjs --fix`
- 도구 파일 복사와 `SHARDS` · `batchId` · `MAJORITY` 수정
- `disputed.json` 생성

이런 것은 모델 한 번 돌릴 값어치가 없다. 네가 하면 몇 초다.

### 넣을 일이 정말 없을 때

`plan.md` 에 **"일감 고갈 · 0-lead 조치 필요"** 를 맨 위에 쓰고, 무엇이 막고
있는지 한 줄로 적어라. 그것이 0-lead 가 가장 먼저 볼 신호다.

## (8) 역할 경계 — 공급 감독관과 겹치지 마라

감독관은 둘이다. 겹치면 같은 일을 두 번 넣거나 `jobs.tsv` 가 섞인다.

| | 진행 감독관 (너) | 공급 감독관 |
|---|---|---|
| 대상 | **이미 열린 배치** | **새 배치 개설** |
| 하는 일 | 대조·판정·감사·재감사 진행 | `next-batch.mjs` 실행 |
| 안 하는 일 | 새 배치를 열지 마라 | 기존 배치를 건드리지 않는다 |

**`node .pipeline/dispatch/next-batch.mjs` 를 실행하지 마라.** 새 배치가 필요하면
`plan.md` 에 적기만 하라. 공급 감독관이 20건 미만이면 알아서 연다.

`jobs.tsv` 에 덧붙일 때는 반드시 락을 거쳐라. 직접 `>>` 하지 마라.

    printf '%s\t%s\t%s\t%s\n' "모델" "제목" "프롬프트" "산출물" | bash .pipeline/dispatch/append-jobs.sh
