작업 폴더는 현재 폴더(bible-mindmap)다. 이 실행에서 너는 '음역 선례 감사자'다. 파일을 고치지 마라. 찾아서 보고만 하라.

배경: batch 02 에서 같은 방식의 감사가 실제 오류를 여러 건 잡았다. 헬라어 ευ 표기 4건이 배포된 bookContext.js 와 어긋났고, 판정 근거 61건이 실제 표기와 모순됐다. 이번에도 그런 자리를 찾는 것이 네 일이다.

1. `.pipeline/task10/WORKER_SPEC.md` 의 확정 표기 규칙과 `.pipeline/task10/final.json` 을 읽어라.
2. final.json 의 `entries` 배열에서 **index 를 3으로 나눈 나머지가 2 인 항목만** 감사하라. 다른 항목은 건드리지 마라.
3. **배포된 데이터와 어긋나는 표기를 찾아라.** grep 으로 직접 대조할 파일:
   `src/data/koreanGloss.js`, `src/data/koreanGlossTopBatch01.js`, `src/data/koreanGlossTopBatch02.js`,
   `src/data/koreanGlossGenesis1Batch01.js`, `src/data/koreanGlossGenesis1Batch02.js`,
   `src/data/bookContext.js`, `src/data/bibleReferences.js`, `src/data/contextChapterCards*.js`.
4. 점검 항목:
   - 같은 lemma·같은 어근이 배포 데이터에 다르게 적혀 있는가
   - 확정 규칙 위반 (연음 기호 잔존 · 장애음 겹자음 받침 · 어말 שׁ · 자음 ו · 유성 쉐바 ə · 헬라어 ευ)
   - note 가 실제 translitKo·translit 와 어긋나는 말을 하는가
   - 같은 조합이 이 배치 안에서 서로 다르게 적혔는가
   - 관용 표기가 굳은 고유명사인데 note 에 그 차이 설명이 없는가
   - SBL 라틴 음역이 lemma 의 모음부호와 맞지 않는가

출력은 `.pipeline/task10/audits/audit-3.json` 하나뿐이다. 다른 파일은 만들지도 고치지도 마라. git 커밋은 하지 마라.

형식(마크다운 코드펜스 없이 JSON만):
{"shard":"3","checked":<개수>,"findings":[{"strong":"H1234","field":"translitKo|translit|note","current":"…","suggested":"…","evidence":"배포 데이터의 어느 파일 어느 표기와 어긋나는지","severity":"high|medium|low","reason":"한국어 한두 문장"}]}

**배포 데이터에 실제 근거(evidence)가 없는 지적은 하지 마라.** 취향 차이는 보고하지 마라. 문제가 없으면 findings 를 빈 배열로 둬라.
다 쓴 뒤 node -e 로 JSON.parse 하고 "audit-3.json findings=<개수> OK" 한 줄만 보고하라.
