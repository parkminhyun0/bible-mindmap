# task6 · 사전 한글 음역 batch 02 · 작업자 공통 명세

## 목표

성경 66권 코퍼스 빈도 상위 300개 Strong 중 아직 한글 음역이 없는 **245개**에
`translit`(SBL 라틴 음역)과 `translitKo`(한글 음역)를 붙인다.

## 절대 규칙

1. **뜻(`glossKo`)은 만들지 않는다.** 이 작업은 음역 전용이다. 뜻은 권위 사전
   게이트가 따로 있으며 이 배치에서 손대지 않는다.
2. 원어 철자·모음부호·악센트·Strong·lemma를 바꾸지 않는다.
3. 배정된 셰이드의 항목만 처리한다. 다른 셰이드·다른 파일을 수정하지 않는다.
4. 다른 작업자의 산출물(`proposals/` 내 다른 파일)을 읽지도 수정하지도 않는다.
   **독립 제안이라야 교차검증이 성립한다.**
5. 소스 코드(`src/`)를 수정하지 않는다. 산출물은 지정된 JSON 하나뿐이다.

## 표기 원칙 (`docs/transliteration-approval-gate.md` 초안 준수)

- 학술(SBL) 표기를 표제로 삼는다.
- 한국어 성경 관용 표기가 다른 고유명사(예: H3068·H1732·H4872)도 **학술 표기를
  표제로 두고**, 관용 표기와 차이가 난 이유를 `note`에 적는다.
- 히브리어: `שׁ/שׂ`(š/ś), 후음 `ח/ה/ע`(ḥ/h/ʿ), furtive patach(어말 후음 앞 a)는
  단어 단위로 판단한다. `ע`는 한글로 따로 적지 않는 것을 기본으로 하되, 관용
  표기가 이미 굳은 낱말은 관용을 따르고 이유를 `note`에 남긴다.
- 헬라어: `ευ`는 후속 자음에 따라 에우/에브/에프가 갈린다. `υ`는 위, `ῥ`는 흐르,
  `σσ`는 ㅅㅅ 계열을 기본으로 하되 관용 표기와 갈리면 `note`에 적는다.
- 엄밀식과 관용식이 같으면 굳이 병기하지 않는다.

## 기존 배치와의 일관성

이미 확정된 표기를 참고해 같은 자모는 같게 적는다. 예:
`אֱלֹהִים → 엘로힘`, `רוּחַ → 루아흐`, `מָשִׁיחַ → 마시아흐`, `דָּבָר → 다바르`,
`אֶ֫רֶץ → 에레츠`, `λόγος → 로고스`, `χριστός → 크리스토스`, `πνεῦμα → 프뉴마`,
`βασιλεία → 바실레이아`, `δόξα → 독사`.
참고 파일(읽기 전용): `src/data/koreanGloss.js`,
`src/data/koreanGlossTopBatch01.js`, `src/data/koreanGlossGenesis1Batch01.js`.

## 입력

`.pipeline/task6/input/shard-<셰이드>.json`

각 항목 필드:
- `strong` Strong 번호 (H/G + 숫자)
- `lang` `hebrew` | `greek`
- `count` 코퍼스 출현 빈도
- `lemma` 원어 표제형 (모음부호 포함)
- `translit` 권위 사전의 라틴 음역. **비어 있으면(히브리어 대부분) 직접 채운다.**
- `glossEn` / `defEn` 참고용 영어 뜻 (음역 판단의 문맥 참고용일 뿐, 옮겨 적지 않는다)

## 출력

`.pipeline/task6/proposals/<셰이드>-<모델슬러그>.json` 하나만 쓴다.
파일명은 실행 명령에 그대로 지정되어 있다.

```json
{
  "shard": "A",
  "model": "<모델 슬러그>",
  "count": 49,
  "entries": [
    {
      "strong": "H4191",
      "lemma": "מוּת",
      "translit": "mût",
      "translitKo": "무트",
      "note": "표기가 갈릴 이유가 없으면 빈 문자열로 둔다."
    }
  ]
}
```

- `entries`는 입력 항목 **전부**를 입력 순서 그대로 담는다. 빠뜨리면 실패다.
- `translit`은 SBL 라틴 음역. `translitKo`는 한글 음역.
- `note`는 표기가 갈릴 수 있는 낱말에만 적는다(관용 표기 차이, 후음 처리,
  furtive patach, `ευ` 문맥 등). 갈릴 이유가 없으면 `""`.
- JSON 외의 설명·마크다운 코드펜스를 파일에 넣지 않는다.

## 끝난 뒤

산출 JSON이 `JSON.parse`로 읽히고 `entries.length`가 입력 개수와 같은지 직접
확인하고 마친다. 그 외 다른 작업은 하지 않는다.
