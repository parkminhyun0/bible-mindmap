# task20 · 사전 한글 음역 batch 02 · 작업자 공통 명세

## 목표

성경 66권 코퍼스 빈도 상위 300개 Strong 중 아직 한글 음역이 없는 **245개**에
`translit`(SBL 라틴 음역)과 `translitKo`(한글 음역)를 붙인다.

## 절대 규칙

1. **뜻(`glossKo`)은 만들지 않는다.** 이 작업은 음역 전용이다. 뜻은 권위 사전
   게이트가 따로 있으며 이 배치에서 손대지 않는다.
2. 원어 철자·모음부호·악센트·Strong·lemma를 바꾸지 않는다.
3. 배정된 셰이드의 항목만 처리한다. 다른 셰이드·다른 파일을 수정하지 않는다.
4. 다른 작업자의 산출물(`proposals/` 내 다른 파일)을 읽지도 수정하지도 않는다.
   **독립 제안이라야 교차검증이 성립한다.**
5. 소스 코드(`src/`)를 수정하지 않는다. 산출물은 지정된 JSON 하나뿐이다.

## 표기 원칙 (`docs/transliteration-approval-gate.md` 초안 준수)

- 학술(SBL) 표기를 표제로 삼는다.
- 한국어 성경 관용 표기가 다른 고유명사(예: H3068·H1732·H4872)도 **학술 표기를
  표제로 두고**, 관용 표기와 차이가 난 이유를 `note`에 적는다.
- 히브리어: `שׁ/שׂ`(š/ś), 후음 `ח/ה/ע`(ḥ/h/ʿ), furtive patach(어말 후음 앞 a)는
  단어 단위로 판단한다. `ע`는 한글로 따로 적지 않는 것을 기본으로 하되, 관용
  표기가 이미 굳은 낱말은 관용을 따르고 이유를 `note`에 남긴다.
- 헬라어: `ευ`는 **유 계열 한 음절**로 적는다. 배포된 사전 38개가 예외 없이
  그렇다 — 피스튜오·유앙겔리온·율로게오·바실류스·테라퓨오·유카리스테오.
  에우/에브/에프로 갈라 적지 마라. (이 자리에 "후속 자음에 따라 갈린다"는
  낡은 문장이 있었고, 그것을 근거로 b11·b12 감사가 배포 데이터와 정반대인
  지적 7건을 냈다. 명세가 배포 현실보다 낡으면 감사가 오판한다.)
- 어두 `ῥ`는 **흐를 붙이지 않는다**. 배포 선례가 레마·레오·뤼오마이·라비다.
  `υ`는 위, `σσ`는 ㅅㅅ 계열을 기본으로 하되 관용 표기와 갈리면 `note`에 적는다.
- 엄밀식과 관용식이 같으면 굳이 병기하지 않는다.

## 기존 배치와의 일관성

이미 확정된 표기를 참고해 같은 자모는 같게 적는다. 예:
`אֱלֹהִים → 엘로힘`, `רוּחַ → 루아흐`, `מָשִׁיחַ → 마시아흐`, `דָּבָר → 다바르`,
`אֶ֫רֶץ → 에레츠`, `λόγος → 로고스`, `χριστός → 크리스토스`, `πνεῦμα → 프뉴마`,
`βασιλεία → 바실레이아`, `δόξα → 독사`.
참고 파일(읽기 전용): `src/data/koreanGloss.js`,
`src/data/koreanGlossTopBatch01.js`, `src/data/koreanGlossGenesis1Batch01.js`.

## 입력

`.pipeline/task20/input/shard-<셰이드>.json`

각 항목 필드:
- `strong` Strong 번호 (H/G + 숫자)
- `lang` `hebrew` | `greek`
- `count` 코퍼스 출현 빈도
- `lemma` 원어 표제형 (모음부호 포함)
- `translit` 권위 사전의 라틴 음역. **비어 있으면(히브리어 대부분) 직접 채운다.**
- `glossEn` / `defEn` 참고용 영어 뜻 (음역 판단의 문맥 참고용일 뿐, 옮겨 적지 않는다)

## 출력

`.pipeline/task20/proposals/<셰이드>-<모델슬러그>.json` 하나만 쓴다.
파일명은 실행 명령에 그대로 지정되어 있다.

```json
{
  "shard": "A",
  "model": "<모델 슬러그>",
  "count": 49,
  "entries": [
    {
      "strong": "H4191",
      "lemma": "מוּת",
      "translit": "mût",
      "translitKo": "무트",
      "note": "표기가 갈릴 이유가 없으면 빈 문자열로 둔다."
    }
  ]
}
```

- `entries`는 입력 항목 **전부**를 입력 순서 그대로 담는다. 빠뜨리면 실패다.
- `translit`은 SBL 라틴 음역. `translitKo`는 한글 음역.
- `note`는 표기가 갈릴 수 있는 낱말에만 적는다(관용 표기 차이, 후음 처리,
  furtive patach, `ευ` 문맥 등). 갈릴 이유가 없으면 `""`.
- JSON 외의 설명·마크다운 코드펜스를 파일에 넣지 않는다.

## 끝난 뒤

산출 JSON이 `JSON.parse`로 읽히고 `entries.length`가 입력 개수와 같은지 직접
확인하고 마친다. 그 외 다른 작업은 하지 않는다.

## batch 02 에서 확정된 표기 규칙 — 반드시 따른다

batch 02(245개)에서 세 모델의 판정과 **이미 배포된 데이터의 선례**를 대조해 아래
다섯 규칙을 확정했다. 이번 배치는 처음부터 이 규칙대로 적는다. 규칙을 다시
논의하지 마라.

1. **베가드케파트 연음**: SBL 라틴 음역에서 `ḇ ḡ ḏ ḵ p̄ ṯ` 같은 구분 기호를 쓰지
   않는다. `b g d k p t` 로 적는다.
   선례 — `ṭôb`(ṭôḇ 아님) · `ʿereb` · `bōqer` · `bādal` · `zāhāb` · `yārad`.
   단 `ṭ ṣ ḥ`(아래점)와 `ā ē î ô`(모음 장음)는 그대로 둔다. 다른 기호다.
2. **다게쉬 포르테(중복 자음)**: 한글에서 받침으로 겹쳐 적지 않는다.
   선례 — `אַתָּה→아타`(앗타 아님) · `כַּפֹּרֶת→카포레트` · `θάλασσα→탈라사` ·
   `אִשָּׁה→이샤` · `מַטֶּה→마테` · `חַטָּאָה→하타아` · `גִּבּוֹר→기보르`.
3. **음절 말 שׁ**: `쉬`로 적는다(`시` 아님).
   선례 — `אֵשׁ→에쉬` · `דְּבַשׁ→데바쉬` · `שֹׁ֫רֶשׁ→쇼레쉬` · `אִישׁ→이쉬` ·
   `חֹדֶשׁ→호데쉬`. 뒤에 모음이 오면 음절 첫소리이므로 샤/셰/시/쇼/슈로 적는다
   (`חֲמִשִּׁים→하미심`).
4. **자음 ו**: `w` 로 보고 `와/웨/위/워`로 적는다(`바/베/비` 아님).
   선례 — `아원` · `타웨크` · `미츠와`.
5. **ע + 홀렘 바브**: `아원` 식으로 적는다. `ע`(ʿ) 자체는 한글로 따로 적지 않되,
   관용 표기가 이미 굳은 낱말은 관용을 따르고 이유를 `note`에 남긴다.

이 다섯 규칙에 해당하는 낱말이면 `note`에 굳이 규칙을 반복해 적지 않아도 된다.
`note`는 관용 표기와 갈리는 고유명사처럼 **설명이 필요한 자리에만** 적는다.
