# Bible Mindmap 작업 지침 v2.1 (GPT↔자비스 파이프라인)

> 이 파일은 GPT가 항상 참조하는 파이프라인 지침의 레포 사본이다.
> 단일 소스(SoT)는 Notion "🔁 GPT↔자비스 작업 파이프라인" DB의 고정 카드
> **"📌 공통 기준·워크플로우 v2 (고정·삭제금지)"**. 둘이 다르면 Notion 카드 우선.
>
> v2.1 변경: **GPT 쪽에서 git·네트워크·gh 의존을 완전 제거**. (기존 v2는 GPT에게
> `git fetch/switch`·"PR 링크"를 요구해 gh 없는 GPT 환경에서 push/PR 시도 → 중단되는
> 문제가 있었음.) 이제 GPT는 파일 내용 생성·전달까지만, git/push/PR/배포는 전부 자비스.

## 📣 3단계 큐사인 (이 세 단어로만 움직임)

| 단어 | 담당 | 의미 |
|---|---|---|
| 🟢 **"픽업"** | GPT | 자비스가 만든 카드(🎯 다음 작업 뷰/포인터 맨 위)를 읽고 DB·데이터 생성 → 3·완료로 |
| 🔵 **"작업"** | 자비스 | 3·완료 카드 검증·통합·로컬커밋 = **승인 직전까지** (푸시·배포 아직 X) → 5·승인대기 |
| ✅ **"승인"** | 자비스 | push+배포+verify:deploy+PR종료+노션 최신화 → 6·승인완료 → **자동 큐잉**(다음 후보 카드 생성·🎯포인터 갱신) |

> ⚡ **자동 큐잉 (2026-08-02)**: "승인"이 끝나면 자비스는 사용자의 별도 "큐잉하자" 없이도 **자동으로** 다음 후보 카드를 만들어 큐에 올린다(관찰카드=다음 성경 책, 정경추적=다음 Tier; 병렬 트랙이면 각 1건). 큐가 비지 않게 유지하며, 방향이 애매할 때만 사용자에게 확인한다.

흐름: 나→GPT `픽업` → GPT완료 → 나→자비스 `작업` → 자비스 완료보고 → 나→자비스 `승인` → 자비스 배포+자동 큐잉.
카드 지정이 필요하면 `"픽업 [영역]"` (예: `픽업 관찰카드`, `픽업 정경추적`).

---

## ■ 기본
- 작업 전 반드시 `bible-mindmap/AGENTS.md` 를 먼저 읽는다.
- 파이프라인 전체 기준은 Notion 고정 카드 "📌 공통 기준·워크플로우 v2"에 있다 (큐사인·상태흐름·유형별 템플릿·신학기준).
- 빌드타임 소스 변형 금지. 릴리스 워크플로우(로컬→커밋→푸시→CI→verify:deploy→Notion→대시보드 LIVE 마지막 갱신)는 자비스가 수행하며 GPT는 관여하지 않는다.
- 위반 시 CI `guard-no-source-mutation.mjs` 가 배포를 자동 차단한다.

## ■ 🚫 GPT 금지 명령 (v2.1 핵심 · 어기면 중단·반려)
- GPT 실행 환경(Codex Cloud)에는 **`gh`도, GitHub 쓰기 인증도 없다.** 그러므로 GPT는 아래를 **절대 실행하지 않는다**:
  - `git push` / `gh pr ...` / `gh ...` / PR 생성·머지 / 릴리스·배포 명령
  - `git fetch` / `git pull` 등 원격 접근 (네트워크 인증 불필요·의존 금지)
  - 로컬 `git switch/checkout -b`, `git commit` 도 **필수 아님** — 해도 원격 반영 아니라 참고용일 뿐. base 검증 목적의 fetch도 하지 않는다.
- 위 명령이 필요하다고 느껴지면 그 지점에서 **멈추지 말고**, 해당 작업은 자비스 몫이므로 **파일 내용 전달(아래 A 방식)로 대체**하고 핸드오프한다.
- 즉 GPT의 산출은 **"신규 파일의 텍스트 + 결과 보고"** 가 전부다. git 상태·원격 반영은 신경 쓰지 않는다.

## ■ 작업 수령 큐사인 (GPT는 "픽업"만 담당)
- 사용자가 **"픽업"** → Notion "🔁 GPT↔자비스 작업 파이프라인" DB의 **"🎯 다음 작업" 뷰**(상태=1·대기 · 우선순위순) 맨 위 카드 1개를 연다. (대시보드 상단 🎯 현재 작업 큐 포인터도 동일 카드를 지정한다.)
- 사용자가 **"픽업 [영역]"** (예: "픽업 관찰카드", "픽업 정경추적") → 해당 영역의 대기 카드를 지정해 연다.
- 카드를 열면 상태를 **"2·진행중(GPT)"** 로 바꾼다.
- 카드 본문 「작업 지시」의 스펙·스키마·규칙을 그대로 따른다. (이 카드가 작업 맥락의 전부이며, 유형별 명령문 템플릿 A/B/C가 반영돼 있다.)

## ■ ★최신화 (stale base 방지 — git 없이 달성)
- GPT는 **원격을 fetch하지 않는다.** 대신 stale base 문제가 원천적으로 안 생기게 아래를 지킨다:
  - **신규 파일만 생성**하므로 기존 파일 최신 상태와 충돌할 여지가 없다 (→ ★범위 격리 준수가 곧 최신화).
  - 기존 구조·연결 지점을 알아야 하면, 그 정보는 **카드 「작업 지시」에 자비스가 최신 기준으로 명시해 둔다.** GPT는 카드에 적힌 구조만 신뢰하고, 로컬에 우연히 남아있는 오래된 파일 구조를 근거로 삼지 않는다.
- 최신 origin/main 위에 얹는 rebase·통합·직렬(1-PR) 관리는 **자비스가 수행**한다. GPT는 PR 개수·순서를 신경 쓰지 않는다.

## ■ ★범위 격리
- 카드에 명시된 "신규 파일"만 생성한다. 기존 tracked 파일은 절대 수정·삭제하지 않는다 (특히 components/utils, 그리고 public/data·public/lxx·public/lxx-lex 등 생성·데이터 디렉토리).
- 기존 파일 연결(import/spread 등)이 필요하면 직접 고치지 말고 「GPT 결과」에 "자비스가 연결할 위치"로 남긴다.

## ■ 정경추적 개념 카드 스키마 (기능-정경추적 영역 전용 · verifier 하드게이트)
- 정경추적 개념(canonicalConcepts) 데이터는 아래 필드를 **개념마다 전부** 포함해야 한다. 하나라도 빠지면 `verify-canonical-concepts.mjs`(predev/prebuild 등록)가 빌드를 막아 반려된다.
  - `emoji`: 개념 대표 이모지 1개 (인덱스 그리드·타임라인 칩에 표시)
  - `category`: 6테마 enum 중 하나 — `redemption`(구속·언약) / `kingship`(왕권·나라) / `presence`(성전·임재) / `creation`(창조·인간) / `revelation`(계시·지혜) / `conflict`(대적·심판)
  - `labelKo` · `labelHe` · `labelGr` · `strong{he:'H..', gr:'G..'}`
  - `canonicalArc`[5~7]{`stage`,`ref`(Book:Ch[:V]),`summary`(첫 30자 개념 간 고유),`covenantLink`(adamic/noahic/abrahamic/mosaic/davidic/new/none),`connectionType`(A~E)}
  - `theologicalNote` · `reformedAnchors[]`
- category/emoji는 v2.1+ 필수. (신규 개념이 creation/revelation/conflict 테마를 채우면 인덱스·타임라인에 자동 편입된다.)

## ■ 신학·저작권
- 모든 신학 콘텐츠는 장로교 개혁주의(WCF·대소요리문답·언약신학·구속사). 이단·비개혁 주장 배제. 판단 애매하면 Notion "✝️ 신학 검증 프로토콜" 및 "📌 공통 기준·워크플로우 v2"의 신학기준으로 자체점검.
- 성경 본문 원문을 그대로 인용하지 않는다(참조·요약·해설만).

## ■ 파일 전달 (A 방식 · 표준이자 유일한 전달 경로)
- 생성한 신규 파일의 **전체 내용을 코드블록 텍스트로** 「GPT 결과」에 붙인다 (첨부·링크·"PR 참고" X — 그 경로들은 자비스에 내용이 전달되지 않는다).
- 파일이 여러 개면 파일마다 경로 헤더 + 전체 코드블록. 잘라내기·"이하 동일" 금지 — 자비스가 그대로 커밋할 수 있어야 한다.
- 커밋·푸시·PR·배포는 전부 자비스가 자신의 인증으로 수행한다.

## ■ 결과 보고 (카드 본문 「GPT 결과」 섹션에 기재 — 자비스가 여기서 직접 읽음. 사용자에게 내용 복붙 금지)
- 생성 파일 목록(신규 경로만) + 각 파일 전체 내용(A 방식).
- 자체 집계표: 항목/장/개념 수 "채움/목표"(예: 6/6, Isa 66/66).
- 완전성·스키마·필드규칙·신학·저작권 자체점검 통과 선언.
- 카드 스펙에 명시된 대상 파일만 신규 생성했고 기존 파일은 손대지 않았음을 명시(★범위 격리 준수 선언). ※ "base가 origin/main 최신인지"는 **자비스가 통합 시 보장**하므로 GPT는 선언하지 않는다.
- 기존 파일에 필요한 연결(import/spread 등)이 있으면 "자비스가 연결할 위치"로 명시.

## ■ 핸드오프 (여기서 멈춤)
- 절대 push·PR·배포하지 않는다. `git fetch`·`gh`·verify:deploy·Notion 대시보드 갱신도 하지 않는다 — 전부 자비스 몫.
- 결과(파일 전체 내용 + 자체집계) 기재 후 카드 상태를 **"3·완료(GPT)→자비스"** 로 바꾸고 종료한다.
- gh·git·네트워크 오류로 막혔다면 그것은 **정상 핸드오프 지점**이지 실패가 아니다. "gh 없어서 중단"이라 보고하지 말고, 위 A 방식으로 파일을 전달한 뒤 3·완료로 넘기면 된다.
- 이후 사용자가 자비스에게 **"작업"**(검증·통합·로컬커밋) → **"승인"**(푸시·배포·마감) 신호를 보낸다. GPT는 관여하지 않는다.
