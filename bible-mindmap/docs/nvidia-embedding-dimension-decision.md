## 결정

기본 평가·후속 인덱스 설계 차원은 **2048차원 유지**로 결정한다.

384차원도 최소 품질 게이트는 통과했지만 2048차원과 비교했을 때 다음 회귀가 확인됐다.

| 지표 | 2048 | 384 | 판정 |
| --- | ---: | ---: | --- |
| Recall@3 | 1.0000 | 0.96875 | 384 하락 |
| MRR | 1.0000 | 1.0000 | 동률 |
| nDCG@3 | 0.99498 | 0.97582 | 384 하락 |
| hard-negative 오탐률 | 0.1875 | 0.3750 | 384 악화 |
| multi-hop Recall@3 | 1.0000 | 0.83333 | 384 하락 |
| multi-hop hard-negative 오탐률 | 0 | 0.33333 | 384 악화 |
| 실패율 | 0 | 0 | 동률 |
| 문서당 float32 벡터 크기 | 8,192B | 1,536B | 384가 81.25% 절감 |

384차원은 저장량을 81.25% 줄일 수 있지만, 현재 성경 정경 검색 평가에서는 절감 효과보다 검색 누락과 오탐 증가가 더 중요하다. 특히 multi-hop 질의에서 정경 개념을 연결하는 능력과 hard-negative 통제가 약해졌다.

## 해석

- 2048차원 Hybrid 후보는 16개 질의에서 Recall@3 1.0을 유지했다.
- 384차원은 전체 16개 질의 중 일부 정답 후보를 Top-3에서 놓쳤다.
- 384차원 hard-negative 오탐률은 2048차원의 두 배였다.
- 두 차원의 token 사용량은 동일했다.
- 보고서의 약 1ms p95는 embedding 생성 후 로컬 검색·순위 계산 시간이며 NVIDIA 네트워크 왕복 시간이 아니다.

## 운영 경계

- 이번 결정은 기본 평가 정책과 향후 인덱스 설계 권고를 2048차원으로 고정한다.
- 운영 검색 인덱스와 기존 성경 DB는 자동 변경하지 않는다.
- 실제 production 인덱스 도입은 별도의 구현 PR, 전체 데이터 verifier, 브라우저 회귀 검사, 사람 승인을 요구한다.
- 향후 corpus와 평가셋이 충분히 커지거나 모델이 변경되면 동일한 bake-off를 다시 실행할 수 있다.
